Scheduled runs (optional: a cheaper or local model for the schedule)
$agent_buttons

$aws_status

Only runs the schedule starts use the scheduled model; Run, webhooks and discussion use the one above. API keys are read from the environment of the process at run time; this page only stores their variable names. Daily access-portal keys stay in ~/.aws/credentials (mode 600) or in AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY and AWS_SESSION_TOKEN. This page never stores them. Paste today's keys into that file; a running process notices the new file without a restart. On a VM, a container or a pod, leave the profile blank and use the attached role. Do not mount a person's credentials file into the cluster.

Database connections are not HTTP, so they are not sent through the proxy. Put cluster DNS (.svc, .cluster.local), the LAN addresses of databases and local model hosts, and 169.254.169.254 in NO_PROXY so HTTP calls (a local model, webhooks, instance metadata) can bypass it. Do not set ALL_PROXY. A shell variable wins over .env. Values here override [agent] in targets.toml for the UI, cron and webhook runs alike.
